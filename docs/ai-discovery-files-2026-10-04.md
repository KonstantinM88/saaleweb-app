# SaaleWeb: AI discovery files, 04.10.2026

## Проверка

- В репозитории был только `public/llms.txt`; `llms-ful.txt`, `llms-full.txt` и `ai-catalog.json` отсутствовали. На production три отсутствовавших URL возвращали 404.
- Старый `llms.txt` содержал 70 уникальных ссылок на `saaleweb.de`; все ссылки на публичные страницы присутствовали в sitemap. Исключения — ожидаемые служебные `robots.txt` и `sitemap.xml`.
- Длина старого файла — около 15 KB. В нём повторялись каталоги услуг/отраслей/городов, а два интерактивных проектных превью описывались рядом с реализованными работами без явного статуса. Новый короткий `llms.txt` ведёт к ключевым страницам, а `llms-full.txt` даёт самодостаточные проверяемые сведения, границы стартовых цен и статусы проектов.
- Значения 600/990/1 990 € и исключение дополнительных функций сверены с текущей страницей цен; бесплатная ручная проверка с 3–5 пунктами — со страницей анализа. Старые slug с историческими числовыми формулировками сохранены, но текст не утверждает эти результаты.

## Решение по `ai-catalog.json`

По [спецификации AI Catalog](https://ai-catalog.io/spec/) каталог предназначен для обнаружения AI-артефактов и вызываемых агентами ресурсов, например MCP server card или A2A agent card. Публичные страницы услуг и кейсы SaaleWeb такими артефактами не являются. У сайта сейчас нет опубликованного, документированного для сторонних агентов MCP/A2A-интерфейса. Поэтому создавать пустой каталог или выдавать сайт и внутренний AI-ассистент за совместимый агентный сервис было бы неточно; `ai-catalog.json` не добавлен. Вернуться к нему можно после появления реального публичного агентного интерфейса и его документации.

## Ограничения и проверка после деплоя

- Локальный production build прошёл TypeScript, ESLint и генерацию страниц. `next start` вернул для `/llms.txt` и `/llms-full.txt` HTTP 200 и `text/markdown; charset=utf-8`, для `/ai-catalog.json` — ожидаемый HTTP 404. Тестовый сервер остановлен, порт 3017 освобождён.
- После деплоя `7267149` оба файла на `saaleweb.de` ответили HTTP 200; тело каждого дословно совпало с локальным файлом. Hostinger отдаёт статические `.txt` как `text/plain`, несмотря на заданный Next.js Markdown-заголовок. Формат содержимого остаётся Markdown и читается корректно; спецификация `llms.txt` не требует отдельного MIME-типа. Это не причина добавлять обработчик запроса или дублировать текст в коде.
- [Предложение формата `llms.txt`](https://llmstxt.org/) описывает короткий Markdown-указатель. `llms-full.txt` — дополнительный подробный файл, созданный по запросу владельца; он не подменяет HTML-страницы, sitemap или robots.txt.
- [Google Search Central](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) прямо указывает, что Google Search не использует `llms.txt` и похожие специальные файлы для ранжирования и генеративных функций. Публикация этих файлов не является обещанием роста позиций или цитирований.
- Отдельный запрос индексирования этих текстовых файлов не нужен.
