## Изменение главной

Порядок: Hero → факты → кейсы → цены → услуги и отрасли → преимущества →
AI-ready → основатель → Google-отзывы → процесс → аудит → FAQ → контакт.

- Первый экран показывает Neue Liebe Nebra и SorgfaltBau; новые WebP не
  содержат вшитых процентов роста. Lighthouse подписан как замер saaleweb.de.
- Услуги и отрасли собраны в компактный блок с прямыми ссылками; подробные
  страницы остаются доступны. Выбор Next.js, WordPress и заказной разработки
  сформулирован через задачу бизнеса.
- FAQ сначала показывает шесть вопросов. Остальные остаются в HTML и
  раскрываются кнопкой; DirectAnswers расположен внутри общего FAQ-блока.
- На мобильных после прокрутки появляется панель консультации и WhatsApp;
  она скрывается при открытом баннере согласия и у заключительного контакта.
- Предыдущие крупные декоративные секции сняты с главной; их компоненты и
  содержимое остались в проекте.

## Исправления поверх пакета

- Устранена гонка при первом открытии баннера: его временное отсутствие во
  время гидратации больше не принимается за сделанный выбор. При недоступном
  localStorage учитывается явное событие выбора.
- Повторное открытие настроек согласия скрывает мобильную CTA-панель.
- Кнопка настроек согласия и закрытый AI-ассистент поднимаются над панелью.
  После открытия и закрытия чата положение кнопки также сохраняется.
- Подписи консультации на DE/RU сокращены для узких экранов.
- На ширинах меньше 480 px отрасли показаны одним столбцом: длинные русские
  названия больше не выходят за карточки. Исправлены переносы и минимальная
  ширина колонок заключительного контактного блока на узких экранах.

## Проверки

Итоговая проверка выполнена после адаптивных исправлений и обновления до
Next.js 16.4.6; приведённые ниже HTTP и браузерные результаты относятся к
этой финальной сборке.

- JSON DE/EN/RU: читается корректно; по 18 обычных FAQ, 6 услуг и 8 отраслей.
- TypeScript: успешно после удаления распакованных частичных копий исходников,
  которые TypeScript ошибочно включал в проект из `temp/`.
- ESLint: успешно.
- Первые сборки Next.js 16.4.3 сгенерировали 247 страниц, но проверка
  безопасности могла завершить команду кодом 1 после генерации. Это не
  ошибка компиляции макета; промежуточный повтор проходил с кодом 0.
- Финальный `npm run build` на 16.4.6: успешно, код 0, 247 страниц.
- Финальный `NEXT_TEST_WASM=1 npm run build`: успешно, код 0, 247 страниц.
  Лог подтверждает `wasm build @next/swc-wasm-nodejs`, его package.json —
  версию 16.4.6. Конфигурация `.mjs` и Webpack сохранены. Это локальная
  проверка совместимости с fallback Hostinger, не проверка его деплоя.
- Неблокирующие предупреждения: устаревающий Edge Runtime и невозможность
  разобрать динамический import для кэша зависимостей `next-intl`.
- HTTP: `/`, `/en`, `/ru` — 200, исходные H1, canonical и четыре hreflang.
  В каждой локали один FAQPage с 24 уникальными вопросами (18 FAQ + 6 прямых
  ответов). 111 уникальных внутренних ссылок с главных ведут непосредственно
  на HTTP 200. Sitemap содержит прежние 229 URL.
  [HTTP-проверка](audits/2026-11-16-homepage-http-check.json).
- Разделение ответов HTML / `text/x-component` и заголовок Vary проверены;
  админка без сессии перенаправляет на вход, robots сохраняет запреты API/admin.
- Браузер: две картинки Hero загружены; 13 основных секций. При первом
  открытии согласия панель скрыта даже после прокрутки. Отказ от аналитики
  разрешает панель; повторное открытие настроек снова её скрывает. Закрытый
  AI-триггер и настройки находятся выше панели. Чат открывается в пределах
  экрана и после закрытия сохраняет корректное положение триггера.
- FAQ: первоначально скрыты 12 дополнительных пунктов; после «ещё» скрытых
  нет, после «меньше» снова 12. Дополнительные вопросы остаются в DOM.
- Финальная адаптивность: DE 320/375/768/1440, EN 320/390/1440,
  RU 320/390/1440 px — без горизонтального переполнения; проверенные тексты
  услуг/контактов не обрезаются. На RU 320 отрасли действительно в одну колонку.
- Панель 390×844 занимает 65 px снизу; закрытая AI-кнопка заканчивается
  на y=768, выше панели (начало y=779). Открытый чат: y=80–840 при высоте
  окна 844. Контактный блок находится в видимой зоне, панель при этом скрыта.
  [Браузерные измерения](audits/2026-11-16-homepage-browser-check.json).
  Реальные заявки, вопросы ассистенту и уведомления не отправлялись.

Локальный запуск `next start -p 3197 -H 127.0.0.1` дал циклический ответ 307
для немецкого `/`, при этом EN/RU работали. Повторный запуск стандартной
командой `next start -p 3197` устранил это без изменения маршрутизации:
все три страницы и проверенные ссылки отвечают 200. На production немецкая
главная также ответила 200. Этот сбой локального запуска не объявляется
регрессией production или основанием переписывать proxy.

## Оценка и оставшиеся вопросы

Результат лучше по структуре: примеры работ и цены видны
раньше, меньше повторов и декоративных пауз, путь к обращению короче.
Увеличение конверсии, рост позиций и улучшение PageSpeed пока не измерены.
DirectAnswers теперь расположен ниже, в общем FAQ: сами ответы и схема
сохранены, но их место в воронке изменилось. После публикации полезно
сравнить охват главной в GSC и повторить тот же AI-бенчмарк.

На старых обложках кейсов в `public/images/cases` всё ещё есть вшитые
неподтверждённые проценты. Это существующий долг, отмеченный и в инструкции
архива; новый Hero использует отдельные очищенные изображения. Обложки и
записи Media в БД этим обновлением не заменены.

Первоначальная сборка обнаружила известные проблемы безопасности Next.js 16.4.3. Официальный
[релиз 16.4.5](https://github.com/vercel/next.js/releases/tag/v16.4.5)
перечисляет семь исправлений; доступна
[16.4.6](https://github.com/vercel/next.js/releases/tag/v16.4.6).
Затрагиваемость каждого сценария отдельно не установлена. Владелец отдельно
разрешил локальное обновление: `next`, `@next/third-parties` и
`eslint-config-next` теперь закреплены на 16.4.6. React, Prisma, схема и
переменные окружения не менялись. Webpack и конфигурация `.mjs` сохранены
для Hostinger; результат проверки SWC-WASM приводится в итогах ниже.

Промежуточный аудит после Next-патча показал семь предупреждений moderate
в одной цепочке ESLint: `minimatch` и шесть зависящих от него пакетов.
Это не семь независимых проблем Next.js. Проверено
[сообщение об уязвимости minimatch](https://github.com/advisories/GHSA-g3hv-75wg-m249).
Обычное `npm update typescript-eslint` обновило транзитивную цепочку с
8.72.0 до 8.73.0 и заменило minimatch 10.2.6 на исправленный 11.0.1.
Принудительные overrides на новую основную версию не добавлялись;
существующий мост совместимости minimatch 3 сохранён. Аудит установки
завершился с 0 уязвимостей. Итоговые отдельные аудиты также успешны:
[полный](audits/2026-11-16-npm-audit.json) и
[production](audits/2026-11-16-npm-audit-production.json) — по 0 уязвимостей.
Первый зависший аудит до обновления был остановлен.
