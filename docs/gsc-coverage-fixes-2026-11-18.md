# GSC: 147 URL с 404, 51 редирект и 108 без индекса — 18.11.2026

## Результат обследования

Из авторизованного интерфейса GSC сохранены **все 306 примеров** трёх
категорий, а не только строки со скриншотов. В интерфейсе указано последнее
обновление 13.11; URL Inspection уже содержит более свежие обходы.
Проверены актуальные HTTP-цепочки каждого примера и все 229 URL sitemap.

| Категория GSC | Текущее состояние опубликованного сайта |
|---|---|
| 404 — 147 | 145 уже дают 308 → 200; один ошибочный URL Wartung действительно 404; ещё один 404 — устаревший файл шрифта |
| Страница с переадресацией — 51 | Все 51 дают один 308 → 200, без циклов и битых целей |
| Просканирована, но не проиндексирована — 108 | 3 не-HTML ресурса, 4 уже перенаправленных адреса, 2 уже индексированных по свежему API и 99 доступных HTML без индекса |

Счётчик GSC не равен числу сломанных страниц сейчас. Нормальные постоянные
редиректы должны исключать исходный URL из индекса; их цели проверяются
отдельно. Google также не обязан индексировать каждую доступную страницу.
[Официальное описание отчёта](https://support.google.com/webmasters/answer/7440203?hl=en).

Оценка исправлений: **лучше** — прекращается образование синтетических URL,
восстанавливается путь к существующей услуге, сокращаются цепочки и
исправляется обнаруженная навигационная изоляция четырёх страниц.
Изменения локальные, без staging/коммита/push/деплоя. GSC-запросы только
read-only; Validate fix, запросы индексирования и подача sitemap не выполнялись.

## Подтверждённый новый 404 и его источник

`https://saaleweb.de/leistungen/website-wartung-Website-Wartung`
сейчас возвращает 404. URL Inspection показывает `NOT_FOUND`, обход
16.11.2026 02:49 UTC и единственный referring URL:
`https://saaleweb.de/leistungen/website-sicherheit`.

На этой исходной странице настоящий `href` правильный:
`/leistungen/website-wartung`. Но в сериализованном React/RSC-потоке
присутствует точно ошибочный путь — как ключ компонента:

```tsx
<Reveal key={`${link.href}-${link.label}`} ...>
```

При href `/leistungen/website-wartung` и label `Website-Wartung` получается
строка из отчёта. Совпадают адрес, содержимое исходной страницы и GSC-referrer.
Извлечение пути Google именно из RSC — обоснованный вывод по этим данным;
пошаговая трассировка парсера Google недоступна. Код такого ключа появился
в `e2d415d` 28.06.2026; дата обхода не является датой создания ошибки.

Исправление:

- В Phase4LandingPage и Phase4LinkCluster ключ теперь равен настоящему href,
  без приклеенного названия. Ссылки и их подписи сохраняются.
- В проектных галереях и ProjectRichText устранены аналогичные ключи
  URL + индекс. Для статических позиций используются не похожие на URL ключи.
- Для уже обнаруженного точного ошибочного URL добавлен постоянный 308
  непосредственно на `/leistungen/website-wartung`. Параметры сохраняются.
  Страница назначения уже индексируется, canonical согласован с Google.

Это конечное точечное правило, не wildcard-перенаправление произвольных 404.

## Остальные 404 и старый шрифт

145 адресов из этой категории уже ведут на существующие страницы. Большая
часть примеров последний раз обходилась до октябрьского исправления
cross-locale HTTP hreflang; это исторические строки. В двух случаях
обнаружена лишняя ступень Performance:

- `/leistungen/proizvoditelnost` → `/leistungen/performance` →
  `/leistungen/performance-optimierung`;
- `/en/services/proizvoditelnost` → `/en/services/performance` →
  `/en/services/performance-optimization`.

Нормализация уже согласованных Performance-объединений расширена на
локализованные старые цели: исторические aliases сразу ведут на конечную
страницу. Новых объединений контента или языков нет.

Исторический URL шрифта `/_next/static/media/Geist_Variable-s.p.0mrjj4bg00-he.woff2`
отдаёт 404. Ни одна из текущих 229 страниц не содержит его имени;
оба реально используемых шрифта отвечают 200. Это не пропавшая коммерческая
страница. Ошибочный редирект на главную или фиктивный файл не добавлен.
Google допускает 404 для удалённых ресурсов без подходящей замены.
[Рекомендации Google по 404](https://support.google.com/webmasters/answer/2445990?hl=en).

## Что означает группа из 108 URL

- Не-HTML ресурсы: `gemuesepfanne-kraeuterrahm.webm`, `favicon.ico`,
  `manifest.webmanifest` — все 200, вне sitemap; индекс страниц им не нужен.
- Четыре старых источника уже перенаправлены: EN Performance, DE Performance,
  DE Wartung и EN Construction. Их корректные цели — 200.
- Две страницы уже имеют `Submitted and indexed` по более свежему обходу
  15.11: `/en/industries/beauty-studio-website`, `/ru/uslugi/seo-halle`.
- 99 оставшихся HTML: 56 EN, 42 RU и одна DE
  `/leistungen/seo-optimierung`. Для них текущий HTTP — 200,
  сохранённый Google fetch — SUCCESSFUL, индексирование разрешено,
  расхождений Google/user canonical не обнаружено.

Это не единая серверная ошибка, которую устраняют переключателем robots.
Страницы уже есть в sitemap; повторное добавление создаст дубли карты.
Нет оснований массово перенаправлять языковые версии на немецкую главную.
Точное решение Google о неиндексации из этих данных неизвестно.

При этом проверка ссылочного графа выявила конкретный недостаток:
четыре сохранённые EN/RU услуги есть в sitemap, но не имеют входящих
`href` с 229 страниц сайта:

- `/en/services/web-development`;
- `/ru/uslugi/razrabotka-sajtov`;
- `/en/services/maintenance`;
- `/ru/uslugi/podderzhka`.

DE-пары ранее были согласованно объединены, а EN/RU оставлены самостоятельными.
Каталог retainedLinks исключил обе группы целиком, не восстановив связи для
EN/RU. Локальная правка возвращает четыре ссылки в соответствующие каталоги
услуг с описанием существующего объёма. DE retired URL не возвращаются.
Это устраняет подтверждённую изоляцию; рост индексирования не гарантируется.

При браузерной проверке EN/RU обнаружено существующее переполнение подробных
карточек услуг на ширине 320 px: flex/grid сохраняли минимальную ширину
длинного русского текста. В каталоге услуг добавлены `min-w-0` для элемента
сетки и текстового блока, а также перенос длинных слов. Тексты, ссылки и
структурированные данные этой правкой не изменены.

У ряда остальных страниц лишь две входящие ссылки и похожая шаблонная
подача. Точных дублей основного текста в проверенной группе не найдено.
Следующий этап — редакционная проверка самостоятельной ценности, примеров
и намерения пользователя, начиная с DE SEO и востребованных EN/RU услуг.
Одно лишь увеличение объёма текста или повторная подача всех 99 адресов
не является доказанным решением.

## Техническая база и результаты проверки

Production: все 229 sitemap URL — 200, один H1, self-canonical,
не менее трёх hreflang, нет запретов индексирования и конфликтующих
HTTP/HTML alternate-пар. Допустимые HTTP hreflang статических маршрутов
проверялись на согласованность, а не считались ошибкой по наличию заголовка.
225 уникальных внутренних href-целей уже отвечают 200; четыре orphan URL
выявлены отдельно. Отсутствие Google-индекса не приравнивалось к HTTP 404.

Финальная локальная сборка: последовательные `typecheck`, `lint` и
`next build --webpack` (Next.js 16.4.6, 247 страниц) завершились успешно.
Существующее предупреждение о deprecated Edge Runtime не блокирует сборку.

На готовой сборке повторно проверены все 306 примеров и 229 sitemap URL:

- 404-группа: 146 адресов дают один 308 → 200; единственный оставшийся 404 —
  неиспользуемый старый шрифт.
- Все 51 штатных редиректа дают один 308 → 200; циклов и битых целей нет.
- Все 108 адресов третьей группы либо отвечают 200, либо ведут на 200.
- Все 229 sitemap URL отвечают 200 с корректными H1/canonical/hreflang и
  разрешением индексирования. Состав карты полностью совпадает с production.
- Изоляция четырёх EN/RU страниц устранена; теперь все 229 страниц имеют
  входящие ссылки с проверенных страниц. Ошибочная Wartung-строка и имя
  старого шрифта отсутствуют во всём HTML/RSC 229 страниц.
- Read-only script `scripts/check-seo-url-integrity.mjs` прошёл 18 проверок:
  один переход, сохранение query, HTML целей, четыре восстановленные ссылки
  и отсутствие плохой строки во всём HTML/RSC шести исходных страниц.
- В браузере проверены конечный Wartung-адрес с query и семь вариантов
  каталогов DE/EN/RU на ширине 320–1440 px. Переполнения документа нет;
  ранее найденный сдвиг RU на 11 px устранён.

Шесть использованных временных файлов удалены; в `temp/` остался только
`.gitignore`. Собственные проверочные процессы 27276 и 23656 остановлены,
порт 3198 освобождён; пользовательский dev PID 35536 / порт 3000 сохранён.
Созданные проверочные вкладки закрыты, viewport сброшен.
HEAD `a90160a`, индекс Git пуст; коммит/push/деплой не выполнялись.

Оценка: лучше — исправлены подтверждённые технические и навигационные дефекты.
Это не доказательство роста позиций, трафика или индексации оставшихся 99 URL.
