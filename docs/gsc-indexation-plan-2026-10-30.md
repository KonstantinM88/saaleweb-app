## Можно ли массово проиндексировать

Для большого числа URL Google рекомендует sitemap; для нескольких важных страниц — запрос переобхода в URL Inspection. Повторение одного запроса не ускоряет сканирование. Ни отправка sitemap, ни ручной запрос не гарантируют индексирование. [Руководство Google](https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl).

Обычные страницы услуг нельзя отправлять через Google Indexing API: он предназначен для `JobPosting` и трансляций `BroadcastEvent` внутри `VideoObject`. Подмена типа страницы и обход квот не используются. [Назначение Indexing API](https://developers.google.com/search/apis/indexing-api/v3/using-api).

Рабочая последовательность: полезное содержание и видимые ссылки → канонический URL 200 → согласованные языковые связи → актуальный sitemap → отправка карты → выборочные ручные запросы и последующая проверка состояния. Добавление второй карты с теми же 49 адресами не создаст отсутствующую гарантию индексирования. Фиктивные даты lastmod не добавлялись.

## Отправка sitemap после публикации

Подготовлен `scripts/submit-reviewed-sitemap.ts`. Он проверяет опубликованные 308 и цели 200, число уникальных URL карты (229) и отсутствие старых DE адресов в `<loc>` и языковых ссылках. Отправка в GSC выполняется только с `--submit`, после этих проверок. Если сервер ещё отдаёт старые страницы, обращений к Google API не будет.

```powershell
$env:Path = 'C:\Program Files\nodejs;' + $env:Path
# Только проверка опубликованного состояния:
node --conditions=react-server --import tsx scripts/submit-reviewed-sitemap.ts
# После успешной проверки, один раз отправить sitemap в GSC:
node --conditions=react-server --import tsx scripts/submit-reviewed-sitemap.ts --submit
```

Скрипт не запрашивает индивидуальную индексацию и не создаёт cron. Успешный HTTP 204 означает принятую отправку карты, а не индексирование 48 страниц. Секреты читаются из существующей конфигурации и не записываются в отчёт.
