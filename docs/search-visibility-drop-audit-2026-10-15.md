# SaaleWeb: снижение показов Google — 15.10.2026

## Вывод

Снижение показов подтверждено. Оно стало особенно заметным 24–26 сентября и сосредоточено на немецкой главной странице. Сайт продолжает появляться в поиске; массовой текущей технической блокировки в проверке не найдено. Индексирование страницы не означает, что Google будет часто показывать её по целевым запросам.

Первый кандидат для дальнейшей проверки — изменение охвата главной в период September 2026 spam update (24.09–08.10). Это совпадение по времени, **не доказательство санкции или установленной причины**. У наблюдаемых запросов позиции часто улучшились одновременно со снижением показов. Данные не позволяют отделить изменения спроса от изменений условий, при которых Google показывает сайт, персонализации или состава поисковых результатов.

## Источники и границы проверки

- Search Console API: ресурс `https://saaleweb.de/`, подтверждённый доступ `siteFullUser`.
- Search Analytics: тип поиска `web`, окончательные данные по 12.10.2026. API помечает `firstIncompleteDate=2026-10-13`; данные 13–14 октября исключены из сравнений.
- Равные периоды 28/28, 14/14 и 7/7 дней; страницы, запросы, пары запрос–страница, страны, устройства. Дополнительно Германия с фиксированным устройством для нескольких основных запросов.
- URL Inspection: 16 приоритетных URL, включая DE/EN/RU главные, услуги, цены, региональные страницы и кейсы.
- HTTP GET всех 231 URL sitemap с User-Agent Googlebot; HTML, H1, canonical и отсутствие noindex. Это проверка публичного ответа с указанным User-Agent, а не доказательство сетевой доступности для всех IP настоящего Googlebot. Реальный успешный обход подтверждается отдельно через URL Inspection.
- Для главной, блога и Webdesign Halle сравнение обычного и двух Googlebot User-Agent: эквивалентные HTML-ответы и метаданные.
- Текущие robots.txt, sitemap и состояние sitemap в API Google.
- История коммитов и официальные объявления Google.

В доступном встроенном браузере Search Console открывает публичную страницу со ссылкой на вход. Авторизованный Chrome не подключён. Поэтому **Manual Actions, Security Issues, Removals, Crawl Stats и полный интерфейс Page indexing не проверены**. Отсутствие явных предупреждений — сообщение владельца, а не подтверждение агента через эти разделы.

Даты суточной статистики GSC относятся к Pacific Time; не следует приравнивать их к датам и времени ежедневного Telegram-отчёта Europe/Berlin.

За 28 дней: 18.08–14.09 против 15.09–12.10 — показы 1 689 → 1 283 (−24,0%), клики 11 → 15, средняя позиция 19,71 → 14,84.

За последние полные недели: 29.09–05.10 против 06–12.10 — показы 241 → 301 (+24,9%), клики 7 → 3. Рост показов последней недели существенно зависит от 119 показов 12.10; одного всплеска недостаточно для вывода об устойчивом восстановлении. Главная получила в этот день 79 показов.

Последний день 14.10 пока содержит только 3 предварительных показа. Его нельзя сравнивать с полными днями и трактовать как новую потерю видимости.

Для 46 запросов, присутствующих в обеих выборках, видимые показы 563 → 217. При фиксированных весах предыдущего периода средняя позиция приблизительно 14,63 → 9,85. Это не полная картина всех запросов: скрытые строки и исчезнувшие поисковые контексты не видны. Сравнение улучшившейся позиции не доказывает, что сайт сохранил охват или постоянно находится на первой странице.

В Germany/desktop `webdesign halle`: 34 → 8 показов, позиция 17,26 → 7,88. Значит, снижение не объясняется только переходом между странами и устройствами. Для Germany/mobile после падения нет видимой строки этого запроса; отсутствие строки не гарантирует абсолютного нуля из-за ограничений детализации GSC.

За последние 28 дней Google для `webdesign halle` и `wordpress agentur halle` по-прежнему выбирает преимущественно главную. Соответствующие страницы услуг индексируются, но ещё не стали основными посадочными в видимой выборке этих запросов. Само по себе это не доказывает каннибализацию.

`searchAppearance` не вернул строки в обоих 14-дневных периодах. Данных недостаточно, чтобы объяснить падение исчезновением конкретного типа расширенных результатов или переходом в AI-выдачу.

## Техническая проверка и связь с обновлениями

- Все 231 текущий URL sitemap вернули прямой HTTP 200, HTML и H1; noindex в заголовках или meta не найден.
- 16 из 16 URL Inspection: `PASS`, `Submitted and indexed`, `ALLOWED`, `INDEXING_ALLOWED`, `SUCCESSFUL`. Google canonical совпадает с ожидаемым.
- Последний обход главной — `2026-10-14T16:36:47Z` (18:36 Europe/Berlin), то есть после исправления 404, обновления стека и публикации нового robots.txt.
- Google загрузил sitemap 09.10, `isPending=false`, 0 ошибок и предупреждений. Sitemap содержит 231 канонический URL.
- Текущий robots.txt: HTTP 200, разрешает публичные страницы, исключает `/api/` и `/admin/`, не содержит неподдерживаемый Host.
- Основное снижение видно 24–26.09. Октябрьские правки контента, 404/hreflang (07.10), обновление стека/Tailwind (07–08.10), объединение Performance (09.10) и удаление Host (15.10) были позже. Эти правки не объясняют начало сентябрьского падения. История Git не является полным журналом изменений хостинга или БД.
- Google официально объявил глобальное September 2026 spam update 24.09, завершение — 08.10. Совпадение требует наблюдения, но не устанавливает причинную связь для SaaleWeb.
- В официальном списке аномалий отчётности не опубликована применимая к этому периоду проблема Web Search. Это не исключает неизвестный или индивидуальный сбой.

Отдельный существующий недочёт: три локализованных каталога блога и 12 категорий не задают явный canonical. Он подтверждён в HTML и исходниках `blog/page.tsx` и `blog/kategorie/[slug]/page.tsx`; соответствующий код предшествует сентябрьскому снижению. Canonical корня `https://saaleweb.de` и `https://saaleweb.de/` эквивалентны и не являются несовпадением. У главной и основных услуг canonical корректен. Недочёт блогов стоит исправить отдельно, без обещания восстановления показов главной.

Текущая проверка не восстанавливает исторические 5xx/429, CDN-ответы или доступность сервера в сентябре. Для этого нужны Crawl Stats и журналы хостинга. Возможное влияние производительности не доказано; ранее остановленную владельцем оптимизацию T1 автоматически не возобновлять.

## Дальнейшие действия

1. После подключения авторизованного Chrome проверить Manual Actions, Security Issues, Removals и Crawl Stats, особенно даты 24–28 сентября; сопоставить с журналами Hostinger при обнаружении ошибок.
2. Отдельно добавить self-canonical в каталог и категории блога, сохранив локализованные URL, hreflang и RSS. Это техническое упорядочивание, а не доказанное устранение причины падения.
3. Продолжать развитие существующих коммерческих посадочных Halle/Saalekreis через предметные доказательства работ, кейсы, понятный состав услуги и контекстные ссылки. Оценивать пары запрос–страница; текущий индекс не подтверждает самостоятельную видимость посадочных.
4. Повторить сравнение после накопления 14 полных дней после завершения обновления. Контроль около 24.10: финальные 08–21.10 против 24.09–07.10, если API уже подтвердит полноту первого периода. Не включать неполные даты ради свежего графика.
5. Измерять реальные квалифицированные обращения отдельно от нескольких кликов и технических тестов; не создавать массовые страницы и не менять URL для реакции на один всплеск или просадку.

Аудит не меняет публичный контент, маршруты, настройки Google или данные сайта. Сохраняются локальный отчёт и агрегированные доказательства; новый деплой для этой проверки не нужен.
