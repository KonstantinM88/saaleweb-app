# Telegram: GA4 и понятный отчёт о трафике — 30.10.2026

## Причина пустого блока GA4

Подключение GA4 работает: проверены ресурс SaaleWeb `545228440`, поток
`G-30BVTE3FPZ`, сайт `https://saaleweb.de`, часовой пояс `Europe/Berlin`.
Readonly Data API за 29 октября вернул 1 активного пользователя, 1 сессию и
6 просмотров. За 28 октября успешный запрос вернул пустой набор строк.
Скриншот отчёта от 29 октября в 08:00 относится именно к 28 октября.

Причина отсутствия строк за конкретный день не установлена: это не доказанная
поломка подключения и не подтверждение нулевого трафика. GA4 зависит от
согласия на аналитику и обработки Google; первая сторона считает иначе.
По данным Google, [обработка может занимать 24–48 часов](https://support.google.com/analytics/answer/11198161?hl=en).

## Что изменено

- GA4 выбирает последний завершённый день с записями среди семи завершённых
  дней. В заголовке стоит фактическая дата; при выборе более раннего дня
  указана причина. Данные за сегодня в этот блок не попадают.
- Сравнение GA4 идёт с календарным днём перед выбранной датой. Если у базы
  сравнения нет строк или произошла ошибка API, показано «сравнение
  недоступно», без придуманного роста от нуля.
- Добавлена PNG-диаграмма собственного счётчика для `/report`, `/week` и
  ежедневного cron: семь завершённых дней и отдельно неполное сегодня.
  Просмотры и оценка посетителей отображаются разными цветами.
- В тексте и карточках есть вчера/позавчера, неделя/предыдущая неделя,
  сегодня/вчера за сопоставимое прошедшее время. Старые непонятные `(0)`
  заменены на «было» и изменение в основном блоке трафика.
- У каждой системы подписан период. GA4 не складывается с собственным
  счётчиком. Дневные идентификаторы посетителей не считаются разными людьми
  за неделю.
- При ошибке картинки остаётся текстовый отчёт; фото и текст отдельно
  отражаются в результате доставки. Разбиение текста и меню сохранены.

## Статус проверки и публикации

- `npm run typecheck`: успешно.
- `npm run telegram:report:test`: 10 проверок успешно; запросы Google и
  Telegram заменены тестовыми. Проверены DST, календарные даты, резервный
  выбор дня GA4, недоступная база сравнения, ошибка запроса актуальности,
  PNG с нулями, разбиение текста и сохранение текста при ошибке фото.
- `npm run lint`: успешно.
- `npm run build` (Webpack): успешно, 247 статических страниц. Первый запуск
  остановился на ошибках типов временного скрипта предпросмотра; скрипт
  удалён после сохранения результатов, затем typecheck, lint и build
  последовательно выполнены повторно. Существующее предупреждение Next.js
  о deprecated Edge Runtime осталось; оно не связано с отчётом.
- PNG на реальных данных просмотрен: подписи и столбцы читаются, пересечений
  не обнаружено. Размер около 112 КБ.
- В 05:03 Europe/Berlin владелец разрешил пробную отправку. Новый отчёт
  отправлен один раз из локально проверенного кода через действующего бота
  с пометкой `[TEST]`: текст 2/2, диаграмма 2/2, HTTP 200 для обоих чатов,
  `partial: false`. [Результат доставки](audits/2026-10-30-telegram-test-delivery.json)
  не содержит идентификаторов чатов и секретов.
- По запросу владельца выполнен полный push: код и результаты проверки в
  коммите `1865ba1` отправлены в `origin/main` и `hostinger/main`.
  Документация о публикации отправляется отдельным завершающим коммитом.
  Успешная пробная отправка из локального кода не означает обновление
  серверного cron. Деплой Hostinger и Linux-окружение Sharp пока не проверены.

Результат лучше для владельца: даты и сравнения понятны, пустой GA4 за вчера
можно заменить последним доступным завершённым днём. Цена изменения — один
дополнительный ограниченный запрос GA4 и один последовательный агрегат
PostgreSQL на построение отчёта, плюс PNG через существующий Sharp.
Схема БД, зависимости, согласия и настройки сбора данных не изменены.
Для серверного отчёта переобход страниц в GSC не требуется.
